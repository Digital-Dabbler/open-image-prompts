# 开发记录：给本地 Web 应用加「开机自启 + 桌面控制台」

> 用途：以后遇到同类需求（本地跑着一个网页服务、用户不编程、要开机自动起、要能点按钮看状态和启停）时，照这份记录做，不用重新踩一遍坑。
> 本文技术化，是给实施者看的；给这台电脑的日常操作说明在 `使用说明.md`。

---

## 一、需求是怎么被拆开的

原始需求（用户原话）：开机自启动、隐藏服务终端、不通过命令行查看服务情况、随时重启或终止、随时开关自启。

关键澄清来自用户：「我并不想把画廊的启动与控制台绑死，控制台开不开都不影响画廊启动」。

这句话决定了整个架构：**控制台不能是画廊的父进程**。否则关掉控制台就把画廊带走，或者必须先开控制台才能看画廊。

于是拆成两条**互不依赖**的链路：

```
登录 Windows
  └─ 启动文件夹\OIP 画廊服务.vbs        ← 只干一件事
       └─ node gallery-service.mjs（静默，无窗口）
            └─ node web/scripts/with_api.mjs dev（脱离父进程常驻）
                 └─ http://127.0.0.1:5173/

双击桌面「OIP 画廊控制台」            ← 另一条独立链路
  └─ wscript open-console.vbs
       └─ 没在跑才启动 node daemon.mjs
            └─ ShellExecute http://127.0.0.1:47825/  → 面板
```

面板发指令（停止/重启/开关自启），画廊执行；面板本身随时可以关掉，画廊不知道也不关心。

## 二、文件职责

| 文件 | 职责 |
| --- | --- |
| `gallery-service.mjs` | 一次性启动器：探端口 → 已运行就不重复起 → 否则 detached 拉起服务 → 轮询健康 → 写状态 → 退出 |
| `daemon.mjs` | 控制台后端：127.0.0.1 上提供状态/日志/启停/自启开关的 HTTP 接口，托管面板页面 |
| `console.html` | 单文件面板，无框架无构建，每 2.5 秒轮询状态 |
| `open-console.vbs` | 双击入口：控制台没起就静默起，然后用默认浏览器打开面板 |
| `使用说明.md` | 面向用户的日常操作 |

运行期产物全部落在项目的 `.oip/daemon/` 下（已被 gitignore）：`gallery.json`（画廊状态）、`console-port.txt`（控制台实际端口）、`service.log`、`console.log`。

## 三、关键设计决策（以及为什么）

1. **画廊进程脱离启动器**：`spawn(..., { detached: true, windowsHide: true, stdio: ['ignore', fd, fd] })` 然后 `child.unref()`。启动器可以退出，服务不受影响；`windowsHide` 保证无窗口；stdout/stderr 直接接日志文件描述符，所以启动器退出后日志还在写。

2. **就绪用健康检查判定，不等 stdout**：轮询 `GET /health`，最多 90 秒。「进程活着」不等于「服务能用」，Vite 从启动到真能打开页面要好几秒。

3. **健康检查要校验内容，不能只看 200**：目标服务的 `/health` 返回 `{ ok, query_concurrency, cache_entries }`，判定条件是 `payload.ok === true && 'query_concurrency' in payload`。同一个端口上别的程序也可能回 200。

4. **端口固定 5173 + strictPort**：地址可以收藏；撞端口时明确报错，而不是悄悄换端口让用户找不到。

5. **控制台端口反而不固定**：47825 起，占用就 +1，实际端口写进 `console-port.txt`，入口脚本读这个文件。控制台是内部工具，不值得为它占一个固定端口。

6. **自启用启动文件夹的 VBS，不用注册表/计划任务/服务**：用户能看见、能删、不需要管理员权限、零系统残留。删除文件 = 取消自启，这是最朴素也最可靠的回退方式。

7. **杀进程前必须校验命令行**：`taskkill /PID <pid> /T /F` 会杀整棵进程树，杀错就是灾难。先取 `Win32_Process.CommandLine`，确认含 `with_api.mjs` 才动手；不匹配就拒绝并返回中文说明。5173 上跑的可能根本不是本项目。

8. **POST 接口要求自定义请求头 `x-oip-console: 1`**：浏览器里任何网页都能 POST 到 127.0.0.1，但跨域请求带不上这个自定义头（会触发预检且被拒）。实测不带头的 POST 返回 403。

9. **状态双源**：进程存活 + 端口健康 + 状态文件三者交叉判断。只看状态文件会被外部杀进程骗到，只看健康检查说不出「上次启动失败的原因」。

10. **HTML 单文件、无构建**：面板只有几百行，引入框架反而要求用户装依赖、跑构建。

## 四、可直接复用的实现要点

**静默常驻子进程（Node 侧）**

```js
const child = spawn(process.execPath, [scriptPath, 'dev'], {
  cwd: REPO,
  env: { ...process.env, OIP_WEB_HOST: '127.0.0.1', OIP_WEB_PORT: '5173' },
  detached: true,
  windowsHide: true,
  stdio: ['ignore', logFd, logFd],
})
closeSync(logFd)
child.unref()
```

**生成开机自启的 VBS（UTF-16LE + BOM，CRLF）**

```js
const script = [
  'Option Explicit',
  'Dim sh, q',
  'Set sh = CreateObject("WScript.Shell")',
  'q = Chr(34)',
  'WScript.Sleep 15000',                       // 等登录后的桌面和网络就绪
  'sh.CurrentDirectory = "' + REPO + '"',
  'sh.Run q & "' + process.execPath + '" & q & " " & q & "' + LAUNCHER + '" & q, 0, False',
].join('\r\n')
fs.writeFileSync(vbsPath, '\ufeff' + script, { encoding: 'utf16le' })
```

**入口 VBS 探测控制台是否在跑**

```vbs
Function HttpOk(addr)          ' 本机只有 MSXML2.XMLHTTP.6.0 可用
  HttpOk = False
  On Error Resume Next
  Set http = CreateObject("MSXML2.XMLHTTP.6.0")
  If Err.Number <> 0 Then Exit Function
  http.Open "GET", addr, False
  http.Send
  If Err.Number = 0 Then
    If http.Status = 200 Then HttpOk = True
  End If
  On Error GoTo 0
End Function
```

**跨进程传递端口**：`console-port.txt` 存纯数字，入口脚本 `IsNumeric` 校验后再用。

**日志轮转**：写日志前检查大小，超过 20 MB 改名成 `.1` 覆盖旧的。

## 五、踩过的坑（按代价排序）

1. **VBS 里没有 C 风格的引号转义。** `sh.Run ""C:\Program Files\node.exe"" & ...` 会被解析成「空字符串 + 裸词」，编译错误「语句未结束」。正确做法是 `q = Chr(34)` 再拼接，或整个命令放在一个字符串里用 `""` 表示内部引号。

2. **VBS 脚本里往上找仓库根要数清楚层级。** `WScript.ScriptFullName` 包含文件名，文件在 `tools\oip-daemon\` 下，需要**三次** `GetParentFolderName` 才到仓库根。少一次的后果很隐蔽：脚本不报错，`sh.Run` 也「成功」，只是 node 找不到入口文件秒退，然后在超时分支弹框——排查了两轮才定位。

3. **`cscript //X` 不是语法检查，它会弹出「选择实时调试程序」并永久挂住。** 校验 VBS 直接 `cscript //nologo <file>` 实跑，或者写个临时副本把 `Sleep` 改小。事后还要检查并清理 `vsjitdebugger` 进程。

4. **`FileSystemObject` 没有 `ExpandEnvironmentStrings`。** 那是 `WScript.Shell` 的方法。写成 `fso.ExpandEnvironmentStrings` 是运行时错误，而 VBS 的运行时错误在隐藏执行时不明显。

5. **PowerShell 5.1 的 `Start-Process -RedirectStandardOutput` 在本机会报 "Item has already been added. Key in dictionary: 'NO_PROXY' Key being added: 'no_proxy'"**（环境变量大小写重复）。需要重定向输出时改用 `& node ... > out 2> err`，或干脆用真正的控制台运行。

6. **PowerShell 5.1 里 `try` 不能当表达式。** `"结果: " + (try { ... } catch { ... })` 直接报「无法将 try 识别为 cmdlet」，必须先赋值再拼。

7. **detached 的启动器是「一次性任务」，会自己退出。** 所以别把它当成守护进程：它写完状态就没了。要判断「现在到底活着没」，靠健康检查，不靠启动器进程。

8. **验证「真的没有窗口」用 `Get-Process | Select MainWindowHandle`**，全为 0 才算过。

9. **杀整棵树要用 `taskkill /PID <pid> /T /F`。** 本项目是 node → python → python 三层，只杀顶层会留下孤儿占着端口。

10. **面板轮询要跳过隐藏页。** `if (document.hidden) return`，否则最小化后还一直打接口。

## 六、验收清单（照着做一遍）

1. 启动器跑通：端口监听、`/health` 200、所有相关进程 `MainWindowHandle = 0`、日志有 Vite 的就绪行
2. 控制台起来后 `/api/status` 字段齐全，面板显示「运行中」
3. 停止 → 端口释放；启动 → 恢复；重启 → 换 pid
4. 不带 `x-oip-console` 头的 POST → 403
5. 开自启 → 启动项 VBS 生成，**检查头两字节是 `FF FE`**；`cscript` 实跑 → 15 秒后画廊静默就绪
6. 关自启 → 启动项文件消失
7. 退出控制台 → 47825 关闭、5173 仍健康
8. 双击入口 → 2 秒左右拉起控制台并打开面板
9. 面板截图存档

本次实测数据可供对照：入口到面板 2.5 秒；开机自启 VBS 执行后 15.2 秒返回、16.7 秒画廊健康；停止旧的手动实例时一次杀掉 4 个 pid。

## 七、迁移到别的项目时改哪些

| 要改的 | 在哪 |
| --- | --- |
| 仓库根、启动命令 | `gallery-service.mjs` 里的 `REPO` / `spawn` 参数 |
| 服务端口 | `gallery-service.mjs` 的 `PORT` |
| 「是不是本项目」的判定 | 健康检查的字段校验 |
| 进程命令行的特征串 | `daemon.mjs` 里杀进程前的校验（本项目是 `with_api.mjs`） |
| 控制台起始端口 | `daemon.mjs` 的 `BASE_PORT` |
| 面板文案与配色 | `console.html` 顶部 CSS 变量（本项目沿用画廊的铜金配色） |

配色可直接抄这几个值：底 `#09090b`、卡片 `#141419`、主文字 `#f4f3ee`、正文 `#b8b7b0`、次要 `#84837c`、强调 `#e2a75b`、错误 `#e0705c`、正常 `#86c9a0`。

## 八、这套方案没有做的事

- **没有守护/自动拉起**：服务崩了不会自己重启，只在登录时起一次。要自动拉起得用计划任务或专门的服务封装。
- **没有开机即用**：登录后延迟 15 秒才起，且 Python 与 Vite 还要几秒，所以开机后大约半分钟内打不开页面是正常的。
- **没有多用户/远程访问**：全部绑定 `127.0.0.1`，只服务本机。
- **没有关闭/注销时的处理**：直接杀进程，不做优雅关闭。
