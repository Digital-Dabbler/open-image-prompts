# OIP 画廊：开机自启 + 可视化控制台（方案 v2）

## 一句话

画廊开机自己在后台静默跑起来，**不依赖任何控制台**；想看情况、想停、想重启、想改自启时，双击桌面快捷方式打开一个网页控制台，用完关掉也不影响画廊。

---

## 一、两条互不依赖的路

这是 v2 的核心改动：**启动链路里没有控制台**。

```
① 开机自启（主链路）
   启动文件夹 VBS ──静默启动──▶ 画廊服务（5173）
                    └─ 启动器写完状态就退出，画廊独立运行

② 管理（可选、按需）
   双击桌面快捷方式 ──▶ 控制台（47825）──▶ 浏览器面板
                        用面板探测画廊、按 pid 操作
                        控制台关掉 / 手动退出 ▶ 画廊完全不受影响
```

- 开机时只起画廊，控制台根本不启动
- 控制台是「按需打开的查看器 + 遥控器」，不是服务的前置条件
- 面板的启动/停止按钮就是**直接操作画廊本身**（启动时用一个独立启动器拉起，与自己无关），不是"通过控制台转发"

## 二、现在是怎么跑的

`start.bat` 做安装动作（uv、npm、下载数据），真正在跑的核心只有一行：

```
node web\scripts\with_api.mjs dev
```

它带起两个子进程（Python 数据接口 + Vite 前端），共 3 个进程，共享一个终端窗口。

「隐藏终端」= 用不弹窗的方式跑这一行，把输出写进日志文件。

## 三、三个角色

| 角色 | 是什么 | 生命周期 |
| --- | --- | --- |
| **启动器** | 一个几十行的小脚本，负责：不弹窗地把画廊拉起来、记下 pid、写日志 | 拉起服务后立刻退出，不常驻 |
| **画廊服务** | 就是现在那条命令，端口固定 5173 | 开机起到关机（或你点停止） |
| **控制台** | 一个常驻的 Node 小程序 + 面板网页，端口 47825 | 你双击才启动，可随时退出 |

三者关系：启动器服务完就走；控制台只是"观察者 + 遥控器"，它自己能起停画廊，但不拥有画廊进程。

## 四、面板上有什么

**状态区**

- 运行中 / 已停止 / 启动中 / 启动失败
- 画廊地址（可点）、PID、启动时间、已运行多久
- 健康检查：数据接口是否正常
- 端口号、是否被其他程序占用

**操作区**

- 打开画廊
- 启动 / 停止 / 重启（停止与重启需二次确认）
- 按钮随状态变化

**自启区**

- 「开机自动启动」开关
- 当前状态 + 启动项文件路径（可点开文件夹核对）
- 说明一句：只在你登录 Windows 后启动，不需要管理员

**日志区（默认收起）**

- 最近 200 行输出，错误行标红
- 「打开日志文件」「复制最后一段错误」
- 启动失败时自动展开并高亮原因

**右下角**：「退出控制台」——关掉控制台本身，画廊继续跑。

## 五、开机自启怎么实现

启动文件夹放一个 VBS：

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\OIP 画廊服务.vbs
```

它做的事：延迟 15 秒（避开开机高峰）→ 静默调用启动器 → 画廊起来 → 启动器退出。

- 不需要管理员权限，不注册 Windows 服务
- **取消 = 面板里关掉开关**（就是删这个文件），去文件夹自己删也一样
- 和现有的「生图词库服务」同一套做法

## 六、「隐藏」到什么程度

- 不出现 cmd 黑窗口，任务栏没有窗口
- 任务管理器里能看到 node / python 后台进程（服务本体，正常）
- 输出写进 `.oip\daemon\service.log`（20MB 轮转）
- 关浏览器、退出控制台都不影响服务；注销/关机服务结束

## 七、停止 / 重启为什么干净

进程树 3 层（node → python → python），只杀外层会留孤儿占端口。所以：

- 停止 = `taskkill /PID <主进程> /T /F` 杀整棵树 → 轮询端口直到真正释放 → 才显示「已停止」
- 重启 = 停止 + 用独立启动器重新拉起，面板显示「正在启动…」直到健康检查通过（2–5 秒）
- 只杀本项目的进程树，不误伤其他 node 程序
- 控制台自己退出时，绝不发送任何"停止"信号

## 八、出错时怎么办

| 情况 | 面板表现 | 你能做的 |
| --- | --- | --- |
| 5173 被别的程序占了 | 启动失败，提示端口被占用，日志有原文 | 面板「改端口」，或关掉占用程序 |
| 环境没装好 | 启动前拦住，提示「请先运行一次 start.bat」 | 跑一次 start.bat，之后不再需要 |
| 服务崩溃 | 状态「已停止」，日志末尾是错误 | 点重启；反复崩就把日志给我 |
| 控制台没响应 | 面板打不开 | 双击桌面快捷方式，它会先把控制台拉起来 |
| 已有手动起的旧实例 | 显示「已在运行（外部启动）」 | 可直接接管停止/重启 |

## 九、会改哪些地方（用户级、可回退）

新增：

- 项目内 `tools\oip-daemon\`（启动器 + 控制台 + 面板页面，约 5 个文件）
- 运行期 `.oip\daemon\`（日志、状态、pid）
- 桌面快捷方式 `OIP 画廊控制台.lnk`
- 启动文件夹 `OIP 画廊服务.vbs`（仅打开自启开关时）
- `tools/oip-daemon/` 纳入项目版本库（与其他代码一起提交，误删可回滚）

不碰：

- `start.bat` / `start.sh` / 项目代码一行不改
- 不动环境变量、注册表，不装第三方依赖（控制台只用 Node 内置模块）

回退：

1. 面板关掉自启开关 → 启动项删除
2. 删桌面快捷方式
3. 删 `tools\oip-daemon` 与 `.oip\daemon` → 恢复原状

## 十、需要你拍板的两件事

**1. 画廊地址固定 5173 还是换一个？**

- A：5173（现在就在用，书签直接有效）　← 推荐
- B：5180 之类，避开其他项目常用的 5173

**2. 桌面快捷方式叫什么？**

- 「OIP 画廊控制台」　← 推荐
- 或你另起

（控制台不随开机启动、可随时退出，这两点按 v2 已定，不再问。）

## 十一、落地顺序

1. 写启动器 + 控制台 + 面板，先只做只读状态（不碰自启）
2. 你验收：面板能看到状态、点停止画廊真关、点启动真回来、退出控制台画廊还在
3. 加自启开关 + 桌面快捷方式，你重启一次电脑确认无黑窗
4. 交付一页说明：怎么开、怎么关、出问题看哪里

## 十二、验收清单

- 双击桌面快捷方式 → 面板出现，显示「运行中」
- 点停止 → 3 秒内「已停止」，画廊打不开；此时退出控制台 → 画廊仍然停着
- 点启动 → 5 秒内「运行中」，画廊正常；退出控制台 → 画廊继续跑
- 点重启 → 不弹黑窗，结束后正常
- 关自启 → 启动项 vbs 消失；开自启 → 出现
- 重启电脑 → 没有黑窗，直接打开 5173 就能用（**控制台全程没启动**）
- 任务管理器：只有 node / python 后台进程，没有 cmd 窗口
